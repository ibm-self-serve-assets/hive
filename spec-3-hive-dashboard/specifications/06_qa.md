# Attendee application acceptance

| Test | Pass condition |
| --- | --- |
| Tool setup | No requirement for local Kafka/container runtime |
| Registration | Token + producer credentials provisions one owned factory and starts a local consumer |
| Reconnect | Existing owned factory reused without resetting it |
| Full path | Hosted factory changes traverse Confluent and local consumer before changing UI |
| Consumer stopped | UI goes stale; cloud factory can continue |
| Start/Pause/Stop | Correct shared lifecycle behavior; clear accepted versus observed statuses |
| Restart zero | Confirmation, new generation and zero snapshot; retry does not reset twice |
| Cross-owner attempt | Server refuses another factory ID; UI does not leak its state |
| Local app restart | Fresh consumer session rebuilds the in-memory view for the still-existing cloud factory |
| Old/new ordering | Late old-generation events never revert the current display |
| Expiry | UI shows expired and explains why commands fail |
| Credentials | No API secret or owner token in browser storage, logs, responses or bundles |
| Kafka ACL | Consumer can read its ten topics/group and cannot read a prepared forbidden test namespace |
| Visual review | Supplied comp, palette and Plex fonts, added lifecycle controls and no clipped content |

Use mock fixtures for UI unit tests, but record a real hosted-server + Confluent integration run separately. Test laptop disconnect/reconnect and explain that the factory remains active while the laptop is offline. Save results/screenshots in reports/controls-results.md.

This package succeeds only when the cloud simulation is separately owned and the local dashboard is an event consumer. A browser rendering an HTTP copy of server inventory does not satisfy the exercise.

Also kill/restart the Simulation Server: show factory lost, require re-registration, and reject old-epoch/factory snapshots. No automatic factory recovery or durable state is expected.
