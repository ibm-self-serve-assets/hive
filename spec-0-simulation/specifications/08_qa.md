# Memory-only server acceptance

Use a deterministic clock and in-memory test factories. No database fixtures or migration tests are required.

- Valid enrollment/producer credentials create one owned paused factory at zero.
- Start/Pause/Stop/Restart follow the shared contract; retries work within one process epoch.
- Different attendees cannot query/control each other's factories or share mutable credentials/state.
- Recipes, nonnegative inventory and delayed-tick handling remain correct.
- Real Confluent observations traverse the assigned topics; connection probes do not create production.
- A broker outage permits continued simulation until the configured buffer cap; recovery in the same process drains it accurately.
- Buffer limits halt the affected factory explicitly without dropping already-accepted records or blocking others.
- Kill/restart the server: all factories, credentials and pending events are gone, the epoch changes, old commands fail, and fresh registration starts at zero with a new factory ID.
- A stale Kafka snapshot never revives a factory or populates a different new factory's UI.
- Planned deployment uses a non-overlapping maintenance interruption; multiple application workers are prohibited.
- TTL expires factories and removes credentials; logs/responses do not expose secrets.

Record real-broker and deployed evidence separately from unit tests in reports/server-results.md. Measure memory usage and buffer growth at the intended cohort size. State clearly that process-restart recovery is intentionally absent.

## Implementation & Testing Gotchas
- When executing pytest / script validation using `uv run`, set `PYTHONPATH=.` from package root `spec-0-simulation/` so `server` and `schemas` modules resolve cleanly.
- Ensure `confluent_kafka` imports fail gracefully into a mock producer fallback for unit test environments where native C-libraries or live Kafka clusters are not present.
- In `FactoryEventBuffer`, track unacknowledged in-flight events with an `in_flight` state to avoid double-publishing or dropping records during retries.
